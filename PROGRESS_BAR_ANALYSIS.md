# Анализ возможности добавления прогресс-бара

## Требование
Добавить вывод прогресс-бара вида `<30%>####---------` во время вычисления метрик SSIM и VMAF.

## Технические требования для реализации

### 1. **Получение длительности видео**
- Использовать `ffprobe` для получения длительности исходного видео
- Команда: `ffprobe -v error -show_entries format=duration -of default=nokey=1:noprint_wrappers=1 <file>`
- Результат: число в секундах (например, `123.456`)

### 2. **Отслеживание прогресса во время обработки**
- FFmpeg выводит в stderr строки вида: `frame=1234 fps=30 q=-1.0 Lsize=N/A time=00:01:23.45 bitrate=N/A speed=1.0x`
- Нужно парсить текущее значение `time=HH:MM:SS.xx` из каждой строки
- Вычислить процент: `(current_time / total_duration) * 100`

### 3. **Проблемы и ограничения**

#### Проблема 1: Текущая архитектура использует `popen()`
- **Текущий код**: использует `popen()` для запуска ffmpeg и читает вывод только после завершения
- **Для прогресса нужно**: читать вывод в реальном времени построчно
- **Решение**: заменить `popen()` на `fork()` + `pipe()` с неблокирующим чтением

#### Проблема 2: Синхронизация вывода
- FFmpeg пишет progress информацию в stderr
- Результат (например, "SSIM: 0.987") выводится последней в stderr
- **Нужно**: разделить парсинг progress и финального результата
- **Решение**: читать stderr построчно, отфильтровать progress, извлечь финальный результат

#### Проблема 3: Переносимость
- Текущий код использует `./ffmpeg` (локальный бинарник)
- Нужно убедиться, что выполняется именно локальный ffmpeg, а не системный

### 4. **Рекомендуемая архитектура изменений**

#### Вариант A: Минимальный (рекомендуется)
1. **Создать функцию `get_video_duration()`** - использует ffprobe для получения длительности
2. **Изменить `compute_ssim()` и `compute_vmaf()`** - добавить параметр прогресс-функции
3. **Создать функцию `print_progress_bar()`** - выводит синхронизированный прогресс-бар
4. **Использовать fork() + pipe()** - для чтения progress информации ffmpeg в реальном времени

#### Архитектурные изменения файлов:
- **ssim.c**: добавить реальное отслеживание прогресса
- **vmaf.c**: добавить реальное отслеживание прогресса  
- **path_util.c**: добавить функцию `get_video_duration()`
- **main.c**: изменение не требуется (интерфейс остаётся прежним)

### 5. **Примерный код для прогресс-бара**

```c
void print_progress_bar(int percent) {
    int filled = percent / 5;      // 20 символов на строку = 5% каждый
    int empty = 20 - filled;
    printf("\r<%3d%%>", percent);
    for (int i = 0; i < filled; i++) printf("#");
    for (int i = 0; i < empty; i++) printf("-");
    printf(" ");
    fflush(stdout);
}
```

Вывод:
```
<0%>--------------------
<15%>###----------------
<50%>##########----------
<100%>####################
```

### 6. **Сложность реализации**

| Аспект | Сложность | Время |

| Тестирование | Средняя | 30 мин |
| **Итого** | | **~2 часа** |

### 7. **Потенциальные проблемы при реализации**

1. **Синхронизация терминала** - при быстрой обработке прогресс-бар может мерцать
   - **Решение**: использовать `\r` для перезаписи строки
   
2. **Потеря финального результата** - нужно убедиться, что результат выводится после очистки прогресса
   - **Решение**: вывести новую строку перед результатом

3. **Случаи без видимого прогресса** - если первый фрейм обрабатывается долго, пользователь не видит прогресс
   - **Решение**: вывести "Processing..." без процентов в начале

4. **Ошибки в получении duration** - если ffprobe не работает, программа упадёт
   - **Решение**: graceful fallback на обработку без процентов

## Вывод

**Реализация возможна, но требует значительного рефакторинга:**
- Замена `popen()` на `fork() + pipe()`
- Добавление функций для получения duration и парсинга progress
- Тщательное тестирование синхронизации вывода

**Рекомендация**: реализовать, но с graceful fallback если что-то не сработает.
